## Okay actual talk

It was a recap of [DBT summit in Las Vegas](https://www.getdbt.com/dbt-summit). There were some thoughts / ideas:

- Context can be useful for agents to avoid making mistakes
- Humans can skip writing SQL by hand, and instead give agents the right context and tools, including ways for agents to get feedback when it goes wrong
- Open source tools and standards can help avoid vendor lock in

There's also DBT 2.0 feature announcements. Some of these include:

- Rust rewrite. Not because it's Rust(TM), but hopefully it means I don't have to wait ages for DBT just to start
- Running unit tests / certain models / tests on duckdb. No need to ping the data warehouse!
- Column lineage to better track how data arrives at the end. Though this is not in the open source version.
- DBT state to reuse tables and skip running. This is also not in the open source version and is paid, but seems like a nice developer UX feature.
